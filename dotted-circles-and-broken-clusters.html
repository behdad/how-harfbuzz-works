Part VI · Scripts

28. Dotted circles and broken clusters

A combining mark needs something to combine with. When a vowel sign begins a line, or follows a space in a script whose signs can’t stand alone, or comes in an order the script doesn’t allow, there is nothing for it to sit on, and a renderer that drew it anyway would hang it over whatever came before, or over nothing. The convention, which the Unicode code charts use for every combining mark, is to show such a mark on U+25CC DOTTED CIRCLE, so that the reader sees a mark and sees that it is out of place. HarfBuzz follows the convention. It doesn’t change the text: the circle is only a glyph in the output, given a cluster of the text it stands in.

There are four places in HarfBuzz that insert one. They were written at different times, for different shapers, and they differ in when they run, in what they test, in what they give the circle, and in whether they check that the font has one at all. The script chapters met each of them in passing. This chapter puts them side by side.

The examples use three small test fonts, built from fonts/dotted-circles-and-broken-clusters/circles.fea. Their glyphs are boxes: a Latin a and a combining acute, and a few Devanagari, Khmer, Myanmar and Brahmi letters and vowel signs. circle.ttf has a dotted circle, a GDEF table and a mark feature that attaches the acute and Devanagari vowel sign U to a base, the dotted circle among them. no-circle.ttf is the same font with U+25CC left out of its cmap (the glyph is still there, but no character reaches it). bare.ttf is circle.ttf without GDEF and GPOS. A few examples borrow fonts from the script chapters. Every result on this page was produced by HarfBuzz 15.1.0 when the page was built.

Four paths

Since 15.1.0: fixed on HarfBuzz main by 74fc8c8 and 2831a8a (17 November 2026), so on main paths 2 and 3 also give the circle U+25CC’s own properties (the last column of rows 2 and 3).

So the vowel constraints are not a fifth way, beside four others: they are one of the four. No other code in 15.1.0 inserts U+25CC. NEWS first mentions them in 0.9.4: “Implement dotted-circle insertion.”

All four obey the buffer flag HB_BUFFER_FLAG_DO_NOT_INSERT_DOTTED_CIRCLE, new in 2.4.0, which turns them all off. hb-shape has no option for it. The order in the table is the order they run in, and an earlier one can settle a case before a later one sees it: a circle inserted at step 3 is a base by the time the syllable grammars run, so it leaves nothing broken.

At the start of a paragraph

The first path is the only one outside the script shapers, and the strictest about when it applies. Here it is whole (hb-ot-shape.cc:552):

static void
hb_insert_dotted_circle (hb_buffer_t *buffer, hb_font_t *font)
{
  if (unlikely (buffer->flags & HB_BUFFER_FLAG_DO_NOT_INSERT_DOTTED_CIRCLE))
    return;

  if (!(buffer->flags & HB_BUFFER_FLAG_BOT) ||
      buffer->context_len[0] ||
      !_hb_glyph_info_is_unicode_mark (&buffer->info[0]))
    return;

  if (!font->has_glyph (0x25CCu))
    return;

  hb_glyph_info_t dottedcircle = {0};
  dottedcircle.codepoint = 0x25CCu;
  _hb_glyph_info_set_unicode_props (&dottedcircle, buffer);

  buffer->clear_output ();

  buffer->idx = 0;
  hb_glyph_info_t info = dottedcircle;
  info.cluster = buffer->cur().cluster;
  info.mask = buffer->cur().mask;
  (void) buffer->output_info (info);

  buffer->sync ();
}

Four conditions: the buffer must be marked as the beginning of a paragraph (BOT), it must have no pre-context, its first character must be a mark (any general category M), and the font must map U+25CC. Buffers explains why BOT is needed and why pre-context overrides it. What goes in is the character U+25CC, before normalization has mapped anything to glyphs, with its own Unicode properties, and with the first character’s cluster and mask:

FontTextOptionshb-shape output
circle.ttf◌́U+0301--bot[dottedcircle=0+500|acutecomb=0@-250,0+0]
circle.ttf◌́U+0301[acutecomb=0+0]
no-circle.ttf◌́U+0301--bot[acutecomb=0+0]
bare.ttf◌́U+0301--bot[dottedcircle=0+500|acutecomb=0@-350,562+0]

The circle is an ordinary character from here on. In circle.ttf, the font’s GPOS attaches the acute to it. In bare.ttf there is no GPOS, and the fallback positioner places the acute over the circle as over any base, because the circle’s general category, So, makes it one. Only the first character is looked at: a mark later in the text, after a space say, gets nothing from this path.

“A mark” is read from the general category alone, so it includes the variation selectors and COMBINING GRAPHEME JOINER, which are default ignorables:

FontTextOptionshb-shape output
circle.ttf︀U+FE00--bot[dottedcircle=0+500|space=0+0]
circle.ttf◌͏U+034F--bot[dottedcircle=0+500|space=0+0]

The selector is then hidden, as default ignorables are, and leaves a visible circle with nothing on it. A paragraph rarely starts with one, but an application that sets BOT on every run of a paragraph and gives no pre-context would get it at the start of every run (inferred from the code).

This path runs for every script and every shaper, including dumber, which a font with morx gets (Choosing a script shaper), and the default shaper that Devanagari falls back to in a font with only DFLT or latn lookups. In the syllabic shapers it comes first. A vowel sign at the start of a paragraph already has its circle when the Indic shaper looks for broken clusters:

The circle is there in the first line, before any of the shaper’s steps; the Indic grammar sees a dotted circle and a vowel sign, a standalone cluster, and its own insertion finds “no broken syllables”.

Broken clusters

The four syllabic shapers each divide the text into syllables with a grammar, as the Indic model, Khmer and Myanmar and the Universal Shaping Engine describe. Each grammar has a catch-all for marks with no base: a broken cluster, a syllable made of what may follow a base, with no base before it. Indic’s is reph? n? complex_syllable_tail (hb-ot-shaper-indic-machine.rl:107), Khmer’s Robatic? (H.cn)* (H | syllable_tail), Myanmar’s k? VS? syllable_tail, and USE’s a tail with an optional leading repha. A lone vowel sign is one in all four. When the scanner finds one, it also sets a buffer scratch flag, HB_BUFFER_SCRATCH_FLAG_HAS_BROKEN_SYLLABLE, so a buffer with none can skip the next step at once.

Which sequences count as broken is the grammars’ business, and it changes with them. NEWS for 10.2.0, for instance, says “Don’t insert U+25CC DOTTED CIRCLE before superscript/subscript digits”.

Where the circle goes

Each shaper calls the same function at the start of its reordering, in the GSUB pause after its first features: Indic in initial_reordering_indic (hb-ot-shaper-indic.cc:983), Khmer in reorder_khmer (:309), Myanmar in reorder_myanmar (:330) and USE in reorder_use (:455). Trimmed, it is (hb-ot-shaper-syllabic.cc:33):

  if (unlikely (buffer->flags & HB_BUFFER_FLAG_DO_NOT_INSERT_DOTTED_CIRCLE))
    return false;
  if (likely (!(buffer->scratch_flags & HB_BUFFER_SCRATCH_FLAG_HAS_BROKEN_SYLLABLE)))
    return false;

  hb_codepoint_t dottedcircle_glyph;
  if (!font->get_nominal_glyph (0x25CCu, &dottedcircle_glyph))
    return false;

  hb_glyph_info_t dottedcircle = {0};
  dottedcircle.ot_shaper_var_u8_category() = dottedcircle_category;
  if (dottedcircle_position != -1)
    dottedcircle.ot_shaper_var_u8_auxiliary() = dottedcircle_position;
  dottedcircle.codepoint = dottedcircle_glyph;

  buffer->clear_output ();
  buffer->idx = 0;
  unsigned int last_syllable = 0;
  while (buffer->idx < buffer->len && buffer->successful)
  {
    unsigned int syllable = buffer->cur().syllable();
    if (unlikely (last_syllable != syllable && (syllable & 0x0F) == broken_syllable_type))
    {
      last_syllable = syllable;

      hb_glyph_info_t ginfo = dottedcircle;
      ginfo.cluster = buffer->cur().cluster;
      ginfo.mask = buffer->cur().mask;
      ginfo.syllable() = buffer->cur().syllable();

      /* Insert dottedcircle after possible Repha. */
      if (repha_category != -1)
      {
	while (buffer->idx < buffer->len && buffer->successful &&
	       last_syllable == buffer->cur().syllable() &&
	       buffer->cur().ot_shaper_var_u8_category() == (unsigned) repha_category)
	  (void) buffer->next_glyph ();
      }

      (void) buffer->output_info (ginfo);
    }
    else
      (void) buffer->next_glyph ();
  }
  buffer->sync ();

It walks the buffer once and puts one circle at the start of each broken syllable, recognized by the low four bits of its syllable byte. The four shapers differ only in the arguments:

Shaper Broken type Circle’s category Skipped first Position
Indic indic_broken_cluster DOTTEDCIRCLE Repha POS_END
Khmer khmer_broken_cluster DOTTEDCIRCLE nothing none
Myanmar myanmar_broken_cluster DOTTEDCIRCLE nothing none
USE use_broken_cluster B R none

The category is the one a typed U+25CC gets from the shaper’s table, a base in every case, so once the circle is in, the broken cluster is reordered like any other syllable with a base. In the Indic shaper it goes through the code for standalone clusters (:962, “We already inserted dotted-circles, so just call the standalone_cluster”), and the circle becomes the base. The Indic position POS_END differs from the POS_BASE_C a typed circle has, but the base search sets the base’s position to POS_BASE_C anyway (:635).

After the repha

A circle goes after any glyphs at the start of the syllable that have the shaper’s repha category: Repha in the Indic shaper, R in USE. Both are categories of characters, not of sequences. In the Indic table one character has Repha, U+0D4E MALAYALAM LETTER DOT REPH (hb-ot-shaper-indic-table.cc:96); in USE, R is given to characters whose Indic syllabic category is Consonant_Preceding_Repha or Consonant_Prefixed (gen-use-table.py:282). With the Malayalam glyphs of the Indic model’s scripts.ttf, the dot reph is passed over, and then moved after its new base:

FontTextOptionshb-shape output
indic-model/scripts.ttfൎാU+0D4E U+0D3E--language=ml[dottedcircle=0+500|ml.dotReph=0+0|ml.aaMatra=0+300]
indic-model/scripts.ttfൎാU+0D4E U+0D3E--language=ml --cluster-level=1[dottedcircle=0+500|ml.dotReph=0+0|ml.aaMatra=1+300]

The reph that RA and a virama make is not a character, and the insertion doesn’t pass over it, though the Indic grammar puts it in the broken cluster (reph?). So RA, virama and a vowel sign get their circle before the RA. The circle becomes the base, the RA a consonant after it, and the reph is never made: the Indic shaper makes one only of RA + virama at the start of a syllable. A circle typed in the same place gives a reph on the circle:

FontTextOptionshb-shape output
circle.ttfर्ुU+0930 U+094D U+0941--language=hi[dottedcircle=0+500|ra=0+500|virama=0+0|uMatra=0+0]
circle.ttfर्◌ुU+0930 U+094D U+25CC U+0941--language=hi[dottedcircle=0+500|uMatra=0@-200,-100+0|reph=0+0]
universal-shaping-engine/deva3.ttfर्ुU+0930 U+094D U+0941--language=hi[reph=0+0|dottedcircle=0+500|uMatra=0+0]

The first line shows RA with a visible virama after the circle, where the second has the reph; it looks like a bug (the comment “Insert dottedcircle after possible Repha” suggests the reph was meant to be kept). When the circle comes in before the shaper looks, from the vowel constraints below, the reph does form on it, and HarfBuzz’s own test, indic-vowel-letter-spoofing.tests, expects exactly that for RA, virama and LETTER I. The third line is USE, under dev3, where RA + virama is a syllable of its own, a virama-terminated cluster, so the vowel sign after it is broken by itself and the reph, formed in the first syllable, stays before the circle.

Clusters

The circle takes the cluster and the mask of the first glyph of the syllable, even when it goes in after a repha, as the second Malayalam line shows: the circle is in cluster 0 with the dot reph, not cluster 1 with the vowel sign. After a space, a vowel sign is a broken cluster in the Indic shaper (USE, as Spaces as bases shows, lets it sit on the space):

FontTextOptionshb-shape output
circle.ttfक␣िU+0915 U+0020 U+093F--language=hi[ka=0+600|space=1+250|iMatra=1+250|dottedcircle=1+500]
circle.ttfक␣िU+0915 U+0020 U+093F--language=hi --cluster-level=1[ka=0+600|space=1+250|iMatra=2+250|dottedcircle=2+500]

At the default cluster level, the vowel sign was already merged into the space’s cluster at step 4 (The pipeline, step by step), because a mark continues the grapheme before it, so the circle gets cluster 1. At level 1 nothing was merged, and it gets the vowel sign’s cluster, 2.

What the circle is to GDEF

The circle goes in as a glyph ID, after GSUB has begun, so it misses two things every other glyph got. Its Unicode properties are all zero, which reads as general category Cc, a control character, with combining class 0. And its glyph properties are zero, because GDEF classes, or synthesized classes in a font without GDEF, were given out at the start of GSUB (hb_ot_layout_substitute_start, and hb_synthesize_glyph_classes, hb-ot-shape.cc:856), before the pause. So the inserted circle is neither a base nor a mark to HarfBuzz, whatever the font’s GDEF says about the dotted circle glyph, until a substitution replaces it.

That mostly doesn’t matter. GPOS mark attachment looks back for the nearest glyph that isn’t a mark (MarkBasePosFormat1.hh:105), and the circle isn’t one, so a mark attaches to it as to a typed circle. The syllabic shapers have no fallback positioning, so without GPOS a mark is left where it is:

FontTextOptionshb-shape output
circle.ttfुU+0941--language=hi[dottedcircle=0+500|uMatra=0@-200,-100+0]
bare.ttfुU+0941--language=hi[dottedcircle=0+500|uMatra=0+0]

Where it would matter is a lookup flag that skips base glyphs: such a lookup skips a typed circle the font classes as a base, but not an inserted one (inferred from the code; not shown).

The pre-context isn’t consulted

The grammars run over the buffer only. A vowel sign at the start of a run is a broken cluster even when the pre-context ends in a consonant it belongs to:

FontTextOptionshb-shape output
circle.ttfिU+093F--language=hi --text-before=क[iMatra=0+250|dottedcircle=0+500]

The first path checks for pre-context, and this one doesn’t. So an application that splits a syllable between two runs, for a change of font or style, gets a dotted circle at the split, whatever context it passes.

Hangul’s tone marks

The Hangul shaper does its own composition in preprocess_text, and there it gives a dotted circle to a tone mark that doesn’t follow a syllable, if the flag allows and the font has U+25CC (hb-ot-shaper-hangul.cc:232). A tone mark with an advance goes before the circle, a zero-width one after it:

FontTextOptionshb-shape output
hebrew-thai-lao-and-hangul/hangul.ttf〮U+302E--language=ko[singledot=0+200|dottedcircle=0+500]
hebrew-thai-lao-and-hangul/hangul.ttf〮U+302E--language=ko --text-before=가[singledot=0+200|dottedcircle=0+500]

It doesn’t look at the pre-context either. Tone marks shows the rest: the circle is made with replace_glyphs, which copies the tone mark’s entry, so the circle has the tone mark’s properties, a spacing mark, and after a lone jamo the fallback positioner treats it as one; and with BOT, path 1 has already put a circle before the tone mark, which to this shaper isn’t a syllable, so the text gets two.

Since 15.1.0: fixed on HarfBuzz main by 2831a8a and 59fa8f0 (17 November 2026), so main gives the circle U+25CC’s own properties, and with BOT uses the circle path 1 inserted as the tone mark’s base, so there is one.

Vowel constraints

Some scripts can write the same vowel in two ways that look alike. In Devanagari, LETTER A with VOWEL SIGN AA looks like LETTER AA, but it isn’t LETTER AA to a search, a sort or a spelling checker, and HarfBuzz’s tests of it are called “vowel letter spoofing”. Microsoft lists such sequences as invalid clusters, and HarfBuzz shows a dotted circle inside them, since issue #1019, in what the code calls an “UGLY UGLY UGLY business of adding dotted-circle in the middle of vowel-sequences that look like another vowel”.

The data

The list is Microsoft’s: src/ms-use/IndicShapingInvalidCluster.txt, whose header gives the dates 2015-03-12 and 2019-11-08 and which defines one property, Indic_Shaping_Invalid_Cluster: “sequences of characters that should be treated as invalid clusters”. It has 103 sequences in 16 scripts: Devanagari, Bengali, Gurmukhi, Gujarati, Oriya, Tamil, Telugu, Kannada, Malayalam, Sinhala, Brahmi, Khojki, Khudawadi, Tirhuta, Modi and Takri. Most are an independent vowel followed by a vowel sign, but not all:

Sequence Kind
U+0905 U+093E, DEVANAGARI LETTER A + VOWEL SIGN AA independent vowel + vowel sign
U+0930 U+094D U+0907, DEVANAGARI RA + VIRAMA + LETTER I a reph on an independent vowel
U+0AC5 U+0ABE, GUJARATI VOWEL SIGN CANDRA E + VOWEL SIGN AA two vowel signs
U+0C3F U+0C55, TELUGU VOWEL SIGN I + LENGTH MARK a vowel sign + a length mark
U+0D91 U+0DCA, SINHALA LETTER EYANNA + AL-LAKUNA independent vowel + virama
U+114AA U+114B5, TIRHUTA LETTER LA + VOWEL SIGN VOCALIC R consonant + vowel sign

gen-vowel-constraints.py turns the list into C++ (and, with --rust, into Rust for HarfRust). It reads Scripts.txt too, to find each sequence’s script from its first character (:189), because the generated function switches on the buffer’s script. It builds a tree of the sequences by their first characters (ConstraintSet.add, :71), and a sequence that begins with a shorter one is absorbed by it: Gujarati A + AA + CANDRA E is dropped, since A + AA already matches. The output, src/hb-ot-shaper-vowel-constraints.cc, records the headers of both files it was made from; in 15.1.0, Scripts-18.0.0.txt.

The code

The function is the Indic and USE shapers’ preprocess_text (hb-ot-shaper-indic.cc:1465, hb-ot-shaper-use.cc:474), so it runs before normalization, on characters. Its Devanagari case begins (trimmed):

What the circle is given

output_glyph makes the new entry by copying the current one, which is the character the circle goes before (hb-buffer.hh:313). So the circle gets that character’s cluster, mask and Unicode properties. _output_dotted_circle clears one of them, the continuation bit, so that the circle starts a grapheme of its own; the rest stay. At the default cluster level, step 4 had already merged the vowel sign into the cluster of the letter before it, so all three glyphs share cluster 0; at level 1 the circle has the vowel sign’s cluster, 1.

The general category it keeps is the vowel sign’s, a mark. In a font with GDEF that is harmless, since GDEF gives the dotted circle glyph its class. In a font without GDEF, HarfBuzz synthesizes classes from the general category, so the circle becomes a mark, and USE, which zeroes marks by class before GPOS (Zeroing marks), takes away its advance. Brahmi is shaped by USE:

FontTextOptionshb-shape output
circle.ttf𑀅𑀸U+11005 U+11038--language=sa[a.brah=0+600|dottedcircle=0+500|aa.brah=0+0]
bare.ttf𑀅𑀸U+11005 U+11038--language=sa[a.brah=0+600|dottedcircle=0@-500,0+0|aa.brah=0+0]
bare.ttf𑀸U+11038--language=sa[dottedcircle=0+500|aa.brah=0+0]

In bare.ttf the circle has no advance and is moved back over the letter A, as a zeroed mark is; a lone vowel sign, which gets its circle from path 4, keeps the circle’s advance. A circle with the properties of U+25CC, as path 1 gives it, would avoid this; it looks like a bug.

Since 15.1.0: fixed on HarfBuzz main by 74fc8c8 (17 November 2026), so main gives the circle U+25CC’s own properties, and in bare.ttf it keeps its advance.

Only adjacent characters

The match is on characters next to each other in the buffer, so anything between them breaks it. A ZWJ, which the Indic grammar allows inside a syllable, hides the sequence; CGJ ends the syllable, so the vowel sign after it gets a circle from path 4 instead:

FontTextOptionshb-shape output
circle.ttfअ⟨ZWJ⟩ाU+0905 U+200D U+093E--language=hi[a.deva=0+600|space=0+0|aaMatra=0+250]
circle.ttfअ◌͏ाU+0905 U+034F U+093E--language=hi[a.deva=0+600|space=0+0|dottedcircle=0+500|aaMatra=0+250]

The first line shows LETTER A and VOWEL SIGN AA together with no circle, which is what the constraint exists to prevent. The same goes for a sequence split between runs: the function doesn’t look at the pre-context, though there, path 4 catches the vowel sign as a broken cluster.

For type designers: give the font a dotted circle, mapped to U+25CC and classed as a base in GDEF, with the anchors of a base for every mark class. Three of the four paths do nothing without it, and the fourth puts .notdef in its place. Expect the inserted circle in places a typed one would be, and test the shaping of lone vowel signs as well as complete syllables.

For programmers: set BOT on the first run of a paragraph and pass the text before every other run as pre-context: path 1 depends on both. The syllabic and Hangul paths don’t read context, so don’t split a syllable between runs. To show text exactly as typed, with no circles, set HB_BUFFER_FLAG_DO_NOT_INSERT_DOTTED_CIRCLE.

Configuration

HB_NO_OT_SHAPER_VOWEL_CONSTRAINTS empties the vowel constraints: the function returns at once (hb-ot-shaper-vowel-constraints.cc:42). It is implied by HB_NO_OT_SHAPE_FALLBACK (hb-config.hh:174), which HB_NO_LEGACY implies (:156). The other three paths have no macro of their own; they go with the ot shaper (HB_NO_OT_SHAPE leaves out hb-ot-shaper-syllabic.cc).

In short

  • Four functions insert U+25CC DOTTED CIRCLE: one at the start of a paragraph, for every shaper; the vowel constraints, for Indic and USE; the Hangul shaper’s, for tone marks; and one for broken clusters, shared by Indic, Khmer, Myanmar and USE. One buffer flag turns them all off.
  • The first needs BOT, no pre-context and a leading mark, and runs before the others, so its circle leaves nothing broken. It inserts the character, with U+25CC’s own properties.
  • A broken cluster is a syllable with no base. Its circle goes in at the syllable’s start, after a repha character but not after RA + virama, as a glyph with the shaper’s base category, the syllable’s first cluster, and no Unicode or GDEF properties.
  • The vowel constraints are Microsoft’s 103 sequences in 16 scripts, generated into code. They insert the character without checking the font, so a font without a dotted circle gets .notdef, and the circle copies the properties of the vowel sign after it, so in a font without GDEF, USE zeroes it.
  • Only the first path reads the pre-context. A syllable split between runs gets a circle at the split.

Since 15.1.0: fixed on HarfBuzz main by 74fc8c8 (17 November 2026), so main gives the vowel constraints’ circle U+25CC’s own properties (the item on the vowel constraints).
